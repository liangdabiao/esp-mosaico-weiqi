## 二、这个应用是什么

一个 **9×9 围棋闯关教学游戏**（raylib-lite 引擎，480×480 触摸屏）。

- **内容规模**：7 章（青铜·入门启蒙 → 王者·高阶战术）共 **154 关**。
  - puzzle 119 关（在盘面落子解题，走错即复位重来）
  - 选择题 32 关（底部选项条）
  - 终局 3 关（停一手 / 提死子 / 完成）
- **玩法**：章节页 → 章节内关卡网格 → 题面（中文折行）→ 答题（触摸落子，
  按交叉点吸附）→ 结算（1~3 星，错 0 次 3 星）。关卡按「上一关已过」解锁。
- **存档**：过关即写 NVS（命名空间 `weiqi`，2bit/关 星级打包），重启从上次关卡所在章继续；
  音量档位独立持久化。
- **音效**：全部由 **RTTTL 合成**（不依赖任何音频素材文件），走 ES8311 codec，
  独立播放任务，入队即返回、不阻塞触摸。
- **中文**：16px 位图字模（379 字）blit，ASCII 走引擎 5×7 字体，题面按字数自己折行。

代码分层（同一份 C 逻辑层同时供固件与电脑模拟器）：

| 层 | 文件 | 职责 |
|---|---|---|
| 入口 | `main/main.c` | 设备：接引擎回调 + GSP 画布 |
| | `main/game_module.c` | 宿主：模拟器适配 + JSON 状态导出 |
| 共享逻辑 | `main/game.c` | 页面导航、触摸热区、全部绘制 |
| 纯逻辑（可宿主编译） | `main/wq/wq_engine.c` | 围棋规则：气 / 提子 / 禁自杀 / 简单劫 |
| | `main/wq/wq_session.c` | 闯关状态机、判题、路径匹配 |
| | `main/wq/wq_content.c` | 154 关数据表（**生成物**） |
| | `main/wq/wq_progress.c` | 2bit 星级打包与序列化 |
| | `main/wq/wq_wrap.c` | 中文按字数折行 |
| 设备适配 | `main/wq/wq_store.c` | NVS 存档与音量 |
| | `main/wq/wq_sfx.c` + `rtttl_player.c` | ES8311 音效 |
| | `main/wq_cjk_font.c` + `wq_cjk_glyph_data.h` | 位图字模 blit（**生成物**） |

## 四、已修复的 2 个问题

### 1. `main/wq/wq_content.c` 与生成器失同步（影响 86 处标记显示）

- **证据**：`python tools/weiqi/gen_content.py --check` → exit 1，报 STALE。
- **症状**：标记字形还是旧版的多字节符号 `▲`(77) / `×`(7) / `□`(2)。而棋盘标记是用
  引擎的 **ASCII 5×7 字体**绘制的，多字节字形会显示成 `?`；同时 `wq_session.c:44`
  用 `glyph >= 'A' && glyph <= 'Z'` 推断光标起点，`▲` 首字节 `0xE2` 不落在该区间，
  起点推断失效（回落到盘心）。
- **修法**：重跑生成器。62 行改动**全部是 `_glyphs` 行**（`▲/×/□` → `A/B/C/X`），
  坐标、题面、正解路径一字未动；`--check` 现已通过。

### 2. `main/game.c` 的 `draw_line_mixed` 越界读

- **证据**：`char one[4] = { s[0], s[1], s[2], '\0' };` 硬假设 3 字节。
- **症状**：遇 2 字节 UTF-8 字符（题面里的 `·`）会多取下一个字符的首字节，
  传给 `wq_cjk_draw` 后解码器会对这个残缺序列再解一次，读到 4 字节栈数组之外 1 字节。
  同文件 666 行的标记字形已改成「按实际长度拷贝」，这一处漏了。
- **修法**：改为 `memcpy(one, s, (size_t)step)`（`step` 只可能是 2 或 3，ASCII 已提前
  `continue`），并在注释里说明原因。

## 五、未修的 3 处小瑕疵（不影响能否刷机）

### A. 字库缺 3 个「会被渲染」的字符：`▲`、`“`、`”`

字库收录 379 个码点，需渲染的非 ASCII 字符共 380 个，缺这 3 个。

| 影响关卡 | 缺失字符 | 设备上的表现 |
|---|---|---|
| 第 4 / 11 / 15 关 | `▲` | 题面「请吃掉标▲的黑子」→ 符号位置**空白**（句子仍读得通） |
| 第 28 / 29 / 30 关 | `“` `”` | 「请点击“停一手”」→ 引号**空白** |

**根因**：字库（`main/wq_cjk_glyph_data.h`）也是生成物，生成于题库引入这些字符之前。
`gen_cjk_font.py` 从 `main/wq/wq_content.c` 取字符集，源字体
`D:/esp/fontsrc/NotoSansCJKsc-Regular.otf` 在位、fontTools 与 PIL 可用，
**重跑一次即可补齐**。

### B. 第 4 关标记字形冲突（`triangle` 与显式字母撞名）

第 4 关同时用了显式字母标记与形状标记：`mark` 形状为 `A / B / C / triangle`，
而 `content.py` 的 `MARK_GLYPHS["triangle"] = "A"` → 棋盘上出现**两个 A**。
题面「下在 A 或 B 是自杀…但下在 C 是允许的…请吃掉标▲的黑子」也因此产生歧义。
第 15 关（`'1' + triangle`）同理，只是不那么明显。

修法有两条，需要你定方向：

1. **保持 ASCII 标记（推荐）**：让生成器为形状标记分配「该关未占用的字母」
   （第 4 关 triangle → `D`），并把 3 处题面的 `▲` 改成对应字母。
   与现有 `MARK_GLYPHS` 设计一致，改动最小。
2. **回到形状符号**：撤销 `MARK_GLYPHS`，把标记改回用中文位图字模绘制（`wq_cjk_draw`），
   这样棋盘显示 `▲` 与题面一致。改动更大，要同时改 `game.c` 的标记绘制路径。

### C. 其它（纯housekeeping，与上机无关）

- `tools/weiqi/validate.sh` 是从别的工程（FoloToy AI Passport）拷来的，引用
  `main/ui_pixel_math.c`、`components/bsp/`、`tools/check_repo.py` 等本项目不存在的
  路径，**直接跑必失败**；它不在刷机链路上。
- `README.md` 里的 `--project projects/weiqi_quest`（下划线）是错的，实际目录名是
  `weiqi-quest`（连字符）。
- 编译有 1 条 warning：`main/game.c:167 'enter_solve_loop' defined but not used`
  （确认为死代码，无任何调用点）。另 2 条是 IDF 自带 `wpa_supplicant` 的 CMake 警告，
  与本项目无关。
- `main/wq/wq_store.c` 有 4 处 `ESP_LOG*` 文案含中文，与「日志一律 ASCII」纪律不符
  （当前编码正常、能编译；改动会牵动 `gen_font.py` 的 charset 清单，故未动）。
- 开机音量存在时序竞态：`wq_sfx_set_volume` 可能早于播放任务 `esp_codec_dev_open`，
  此时音量停在基准 58 而非 58×80%≈46（纯观感）。BSP 的
  `bsp_audio_codec_speaker_init()` 内部是单例，两处调用共享同一句柄，安全。

### 关于日志里刷屏的 `Malformed report header`

日志中出现大量 `W cst9220: Malformed report header: first=0xab marker=0xab`（约 0.5 条/秒）。
查驱动源码 `managed_components/espressif__esp_lcd_touch_cst9220/esp_lcd_touch_cst9220.c:682`：

```c
if (report[0] == CST9220_REPORT_ACK || report[CST9220_REPORT_HEADER_SIZE - 1] != CST9220_REPORT_ACK) {
    ESP_LOGW(TAG, "Malformed report header: ...", report[0], report[6]);
    *point_num = 0;   /* 当作「本次无触点」 */
    return ESP_OK;
}
```

`CST9220_REPORT_ACK = 0xAB`。日志里 `first=0xab`，即读到的是**上一次 ACK 回显**，
驱动按「本次无触点」处理并正常返回。频率约 0.5/s，远低于触摸轮询，说明多数轮询读到的是
合法报文。且 `weiqi-quest / gomoku_duel / qiaopi-quiz / little-prince` 四个工程的该组件
**源码逐字节相同、版本同为 `^1.2.0`** —— 属工作区既有现象，非本项目引入。

**结论**：判为良性噪声。但**触摸手感与画面观感须人工确认**（硬件相关行为不能由日志推定）。

### ① 三处小瑕疵

**A. 字库缺字（根因在第 24 行的过滤规则，不在题库）**

`tools/weiqi/gen_cjk_font.py` 的字符过滤只收 `ord(c) >= 0x2E80`（CJK 与全角标点），
而题面里的 `“` `”`（U+201C/D）、`▲`（U+25B2）都在其下 —— 所以它们从来没进过字库，
设备上整块消失。修法：

- 过滤规则补上通用标点（U+2010–206F）、带圈数字、几何图形（U+25A0–25FF）、`·` `×`；
- 新增**母字体覆盖校验**：清单里有母字体没有的码点就直接报错退出（原来只在 docstring 里
  承诺「缺失会报错」，代码里并没有实现）；
- 新增 `--check` 模式，纳入 `validate.sh`。

结果：字库 379 → **381** 个字形（补进 `“` `”`），覆盖核对 **缺失为空**。

**B. 标记字形撞名（实际是 6 关，不只是第 4 关）**

用「同一关内不同形状标记是否拿到同一字形」重查，旧映射下撞名的有
**第 4 / 51 / 72 / 76 / 78 / 116 关**（第 4 关是 A/B/C + triangle→A；第 76 关是
1/square→B + 显式 B）。修法：

- `content.py` 新增 `level_mark_glyphs()`：显式字母先占，形状标记顺延到本关第一个
  未被占用的字母（第 4 关 triangle → `D`）；
- `gen_content.py` 改用它产出字形数组；
- `levels.txt` 里 3 处引用 `▲` 的题面同步改成实际字形（第 4 关 → 「标 D 的」，
  第 11 / 15 关 → 「标 A 的」）。其余 3 关题面只说「被标记的棋子」，不含字母，无需改。

结果：撞名关卡 **6 → 0**，题面与盘面字形一致。

**C. housekeeping**

### ② BOOT 键 = 返回

BSP 的按键表里只有 AI 键，BOOT 键（`BSP_BUTTON_BOOT_GPIO` = GPIO61）要自己建。
关键是**跨任务安全**：按键回调跑在 button 组件自己的任务上，直接改游戏状态会和
渲染/更新抢同一份 state。所以：

```
按键回调 → MosaicoGamePostDeviceEvent(BUTTON) → 引擎事件队列
        → on_event（游戏任务）→ game_request_back()
```

页面语义与各页已有的返回热区一致：LEVELS→章节页、BRIEF→关卡列表、SOLVE→放弃本关、
RESULT→关卡列表；**已在章节页时不动作**（首页误触不该把玩家踢出应用）。

### ③ 题面文字加大 100%（16px → 32px）

- 字模新增整数倍放大接口 `wq_cjk_draw_scaled/wq_cjk_width_scaled/wq_cjk_pitch`
  （每像素画成 2x2 方块，笔画是实的，不做插值）；
- BRIEF 版式：每行 **12** 字（字距 36px，正文可用宽 448px）、行高 **40px**、
  标题与正文同步 2 倍；`_Static_assert` 把「每行字数 × 字距 ≤ 可用宽」钉在编译期；
- 放大后最长题面 10 行 = 400px > 视口 296px，**5 关会超一屏**（其余 149 关不用滚），
  所以题面区支持上下拖动 + 右侧滚动指示；正文用 `BeginScissorMode` 裁到视口内，
  滚动上限与抬手都吸附到整行，避免停在半行上。

> 踩到的坑：`brief_scroll_max` 我一开始只在 `render_brief` 里算，而手势发生在
> **update/input** 阶段 —— 无头模拟下渲染还没跑过，第一次拖动读到 0、被夹成"不能滚"。
> 版式因此收进实例（`brief_wrapped` + `brief_scroll_max`），由 update 与 render 共用。
> 这是先跑模拟器而不是直接上机才发现的。
